## 2. Null Microbiome Simulation Framework

I developed the initial simulation script:

```text
scripts/simulation/generate_null_dataset.py
```

The purpose of this script is to create a **controlled null microbiome dataset** for pipeline validation.

### Simulation design
- **50 total samples**
- **25 Control samples**
- **25 Case samples**
- **100 taxa**
- **0 truly differentially abundant taxa**
- **Random seed:** 42
- **Target mean library size:** 10,000 reads/sample
- **Dirichlet concentration:** 0.5

### Simulation logic

The simulation follows this general workflow:

```text
Simulation parameters
        ↓
Dirichlet baseline composition
        ↓
Variable library sizes
        ↓
Multinomial count generation
        ↓
50 samples × 100 taxa
        ↓
Known null ground truth
```

### Scientific purpose

The Case and Control groups are generated from the same underlying abundance distribution.

Therefore:

```text
True differentially abundant taxa = 0
```

This makes the dataset a useful calibration control.

If a differential-abundance method identifies significant taxa in this null dataset, those discoveries can be interpreted as potential false positives.

### Observed results

| Maximum library size | 10,191 |
| Zero fraction | 4.68% |
| Mean count per taxon-sample cell | 99.94 |
| Median count per taxon-sample cell | 43.00 |

### Initial interpretation

The dataset successfully behaves as a **controlled low-sparsity null baseline**.

The observed mean sequencing depth of 9,994.22 reads/sample is very close to the intended 10,000-read target.

However, only **4.68% of taxon-by-sample cells are zero**, meaning this initial dataset is relatively dense compared with many real microbiome datasets.

For that reason, this dataset should be treated as:

> **Null Baseline — Low-Sparsity Scenario**

rather than as the final realistic microbiome simulation.

Later simulations should explicitly vary sparsity.

## 5. Rationale for Starting With a Null Dataset

The first experiment was intentionally designed with no true biological difference between Case and Control groups.

This allows the pipeline to be validated under a condition where the expected answer is already known.

### Logic

```text
NULL DATASET
True DA taxa = 0
        ↓
Run DA methods
        ↓
Check for significant taxa
        ↓
Assess possible false-positive behavior
        ↓
Validate pipeline
```

This staged approach allows implementation problems, preprocessing issues, or statistical calibration problems to be identified before the project scales to more complex simulations.

The principle is:

> **Validate correctness first, then increase realism and scale.**

## 6. First Four-Method Differential-Abundance Comparison

The same null dataset was tested using four differential-abundance approaches:

1. **CLR/Wilcoxon**
2. **ALDEx2**
3. **ANCOM-BC**
4. **DESeq2**

### Initial results

| Method | Taxa Tested | Significant Taxa | Minimum Adjusted p-value |
|---|---:|---:|---:|
| CLR/Wilcoxon | 100 | 0 | 0.3499 |
| ALDEx2 | 98 | 0 | 0.8795 |
| ANCOM-BC | 98 | 0 | 0.0553 |
| DESeq2 | 98 | 0 | 0.7181 |

### Key findings

- All four methods identified **0 significant taxa**.
- This agrees with the known ground truth of **0 true DA taxa**.
- CLR/Wilcoxon tested all 100 taxa.
- ALDEx2, ANCOM-BC, and DESeq2 returned usable results for 98 taxa.
- Two taxa were all-zero across samples and were handled differently by the methods.
- Adjusted p-values differed across methods even though all methods agreed on the final significance outcome.

### Initial interpretation

The four methods agreed on the overall null conclusion, but they did not behave identically.

This is an important early example of the core project question:

```text
Data characteristic
        ↓
Method-specific behavior
        ↓
Agreement or disagreement
```

## 7. Formal Null Dataset QC Audit

I created the QC script:

```text
architha/scripts/evaluation/audit_null_dataset.py
```

The purpose of this script is to programmatically verify that the null dataset is structurally valid before scaling the simulation study.

### Checks performed

The script evaluates:

- count-table dimensions
- unique taxon identifiers
- unique sample identifiers
- numeric count values
- non-negative counts
- integer counts
- metadata sample count
- sample ID alignment
- sample ordering
- Control/Case balance
- library-size consistency
- zero-library samples
- overall zero fraction
- taxon prevalence
- all-zero taxa
- ground-truth dimensions
- count-table / ground-truth taxon alignment
- null DA status
- null effect sizes
- group-level library-size summaries

### Why this matters

A successful script run does not automatically mean the simulated data are scientifically valid.

The audit provides a formal reproducibility and integrity checkpoint before repeated simulations are generated.

## 8. All-Zero Taxa as an Important Methodological Observation

The four-method comparison showed that some taxa were handled differently across methods.

The all-zero taxa observed in the null dataset help explain why:

```text
CLR/Wilcoxon → 100 taxa tested
ALDEx2       → 98 taxa tested
ANCOM-BC     → 98 taxa tested
DESeq2       → 98 taxa tested
```

This is relevant to the broader project because it demonstrates that even before significance testing, data characteristics can influence which features each method is able or willing to analyze.

This becomes a useful example of:

```text
All-zero taxa
        ↓
Method-specific filtering
        ↓
Different number of taxa tested
```
